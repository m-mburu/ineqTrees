## Preserve the statistical contracts

- Preserve sampling weights, weighted midpoint ranks and tie handling.
  Report exclusions and the resulting analysis population.
- Preserve the population-style weighted covariance used by current
  scoring. Do not reintroduce a finite-sample correction as a style fix.
- CI, CIg and CIc use fractional ranks. L uses socioeconomic levels.
  Preserve the warning about negative socioeconomic levels for L.
- Preserve the distinction between signed indices and the absolute
  impurity used to search splits. Keep SHAP signs and percentage
  denominators explicit.
- Current CIc uses an observed outcome or prediction range. Do not change
  it to fixed theoretical bounds incidentally. A change to that definition
  requires a separate methodological decision and aligned tests/docs.
- Preserve held-out partition gain, prediction metrics and surrogate-tree
  diagnostics as distinct quantities. Select tuning parameters within
  index type; raw scores across CI, CIg, CIc and L are not interchangeable.
- Preserve small-factor exhaustive search, its size guard, R/C++ parity,
  existing aliases and ordinary fitted-model prediction behaviour.

## Repair in bounded stages

For each stage, add a regression check that fails on the audited behaviour,
make the smallest coherent repair, regenerate the affected outputs and run
the relevant tests. Keep independent fixes reviewable.

### 1. Repair fold construction and resample validation (F1)

Work in `dev/model_selection.Rmd`.

- Replace singleton-unsafe sampling with index-based shuffling, for
  example `idx[sample.int(length(idx))]`.
- Explicitly assign rows with missing strata, or reject them with an
  informative documented error. Never leave zero-valued assignments.
- Allocate across small strata so the requested folds are populated when
  feasible. Preserve reproducibility and the existing seed-restoration
  contract.
- Validate user-supplied fold IDs before coercion. Check missing IDs,
  non-empty training/validation sets and complete row coverage for ordinary
  v-fold CV. Preserve legitimate repeated or overlapping assessments in
  supported `rsample` designs; do not impose one-assessment-per-row there.
- Check resample indices and their correspondence to the supplied data.
  Equal row counts alone do not establish observation identity.

Acceptance: cover missing and singleton strata, strata smaller than `v`,
invalid fold IDs and ordinary balanced folds. Every ordinary CV row must
receive one valid assessment fold. Include one public tuning smoke test
that inspects the actual assessment row IDs.

### 2. Make OOB predictions truthful (F2)

Work in `dev/ci_tree_models.Rmd`.

- Use only trees where a training observation was out of bag. Return `NA`
  with a useful diagnostic when no such tree exists, or use a documented
  explicit error policy. Never fill these values with in-sample estimates.
- The simplest reliable identity rule is to require omitted `newdata` for
  OOB prediction. If explicit training data remain supported, establish
  identity and row order before applying the mask.
- Define and test how `OOB` interacts with `type = "node"`; do not silently
  ignore it. Leave ordinary response and node predictions compatible.

Acceptance: test full-sample trees with no OOB coverage, partial coverage,
and unrelated/reordered same-size data. For covered rows, compare the
result with the mean of explicitly eligible member-tree predictions.

### 3. Preserve SHAP feature and observation identity (F3-F4)

Work in `dev/shap_decomposition.Rmd`.

- Keep rank, weights and predictions outside the feature table, or allocate
  checked unique temporary names. Real feature names must never be replaced.
- Retain DALEX observation IDs until all inputs are aligned. Prefer an
  explicit ID-based contract for ranks, predictions and weights. If keeping
  a positional interface, document and enforce its row-order contract.
- Detect missing IDs and duplicate ID-feature pairs before reshaping. Do
  not accept `dcast()` counting duplicate attributions as an implicit fix.

Acceptance: use features named `rank__`, `weights__` and `prediction__`,
permuted/nonconsecutive DALEX IDs, duplicate pairs and missing feature
values. With matched observations, long and wide representations must
give the same decomposition. Check supplied predictions against the
baseline-plus-attributions example and an independent hand calculation;
a zero additivity gap alone is insufficient.

### 4. Validate numeric inputs at public boundaries (F5)

Work in the ranking, SHAP and model-selection flat files. Check downstream
yardstick wrappers if their behaviour changes.

- Reject negative weights. Treat zero weights and missing rows according
  to an explicit documented policy and record the retained population.
- Reject infinite attributions, rank/level values, outcomes, predictions
  and weights before calculation. Handle NA/NaN under a deliberate
  missing-data policy. Check usable weight totals as well as each element.
- Validate probability metrics against their documented domain, including
  binary truth for log loss and a finite `eps` strictly between 0 and 0.5.
  Validate predictions before clipping valid boundary probabilities.
  Do not constrain continuous-outcome squared error without deciding its
  intended contract.
- Distinguish invalid inputs from legitimate zero/constant/singleton node
  behaviour. Avoid changing existing degenerate-node conventions through
  an unrelated validation patch.
- Reuse focused validation where it removes real inconsistency. Keep
  repeated C++ scoring efficient by validating at the appropriate boundary.

Acceptance: exercise each affected exported entry point with valid inputs,
negative/zero weights, NA, NaN, positive/negative infinity, empty retained
data and zero denominators. Assert informative errors or documented
missing results. Compare valid scores with independently computed values.

### 5. Make tuning eligibility explicit (F6)

Work in `dev/model_selection.Rmd`.

Use a documented conservative default that requires finite scores on the
intended assessment folds before automatic selection. If partial-fold
selection is retained, make it an explicit option and display its coverage.
Track fit, prediction and scoring failures separately. Return a clear
no-eligible-candidate result when a type has no usable scores.

Acceptance: test a high mean from one surviving fold against a complete
candidate, an all-failed type and a non-finite score. Exercise the public
tuner, `ci_select_best()`, collectors and refitting. Ensure no unscored
candidate is presented as a validated winner.

### 6. Make split thresholds reproduce scored partitions (F7)

Change the R flat file and maintained C++ source together. Use a
numerically safe threshold rule and verify that its comparison convention
reproduces the membership used for scoring. Account for adjacent floating
point values as well as overflow. Reject unsupported non-finite predictors
at a clear boundary.

Acceptance: test ordinary, very large positive/negative and adjacent
representable predictor values. Compare candidate membership with actual
`partykit` routing and check fitted-tree predictions. Keep R/C++ agreement,
but include an independent expected partition.

### 7. Reconcile generation and finish focused cleanup (F8-F9)

- Correct fusen ownership mappings after confirming the actual emitted

- Update C++ status prose to match the implemented default and distinguish

- Remove tracked compiled objects/libraries and add appropriate ignore

- Improve spacing, long calls and names in the functions changed above.

- Split large flat-file responsibilities only where ownership becomes
